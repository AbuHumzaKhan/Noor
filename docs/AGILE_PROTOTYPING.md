# Agile + Prototyping Model

Noor will use a hybrid Agile + Prototyping development model.

## Cycle

1. Define a small capability slice.
2. Build the thinnest working prototype.
3. Test it against a real task.
4. Capture failures and evidence.
5. Refine architecture and interfaces.
6. Add automated tests.
7. Document the capability.
8. Promote the capability only after verification.

## Sprint rules

- One meaningful capability at a time.
- Avoid speculative infrastructure.
- Prefer measurable acceptance criteria.
- Keep changes reversible.
- Do not call a feature complete merely because code exists.
- Completion requires working behavior plus verification.

## Definition of Done

A capability is done when its implementation, configuration, tests, documentation, security boundary, and real-world verification are present at the required maturity level.
